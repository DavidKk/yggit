## 1. 产品背景与定位

### 1.1 现状与定位辨析

在现代化研发中，开发者频繁面对跨仓库、多分支、多 Worktree 的复杂状态：

- 版本发布后，十几个关联微服务或前后端项目的默认分支需要同步；
- 多个 Feature 分支同时推进，各分支落后于主干、部分存在潜在冲突；
- 多个开发分支在测试分支上交叉集成，进入预发分支后，需要确认相关改动及测试阶段的冲突解决结果是否保留；

**Yggit Workdesk 的核心定位**：

- **不重复** GitHub / GitLab 的 Web PR/MR 审批流、工时管理或 CI/CD 统计仪表盘；
- **不重复** Jira / Trello 式的通用敏捷项目看板；
- **专注 Git 真实研发场景**：通过确定性的程序化 Git 规则检测，自动聚类为**具体、可执行的 Git 任务卡片**；
- **极简下钻与证据定位**：用户在看板中概览卡片，点击查验提交与文件差异，并按需调起现有的 Yggit Git Agent 辅助决策。

```text
┌─────────────────┐     ┌───────────────────┐     ┌──────────────────┐     ┌───────────────────────┐
│ Git 状态与规则检测 │ ──> │ 智能聚类成工作卡片   │ ──> │ 极简下钻查验证据   │ ──> │ 定位 Git / Agent 协作 │
│ (确定性程序驱动)    │     │ (4个基础工作分类)   │     │ (左清单 / 右证据) │     │ (一键直达或药丸唤起)   │
└─────────────────┘     └───────────────────┘     └──────────────────┘     └───────────────────────┘
```

## 2. 核心设计原则

1. **一卡片 = 一件具体工作**：
   不把几百条原子检测异常（Findings）平铺给用户。依据研发目标（如“同步默认分支”、“核对跨分支集成结果”）聚合为卡片；每个卡片聚合多项目、多分支、多 Worktree 的子任务。
2. **程序负责可靠发现，Agent 负责理解与协助**：
   分支是否分叉、能否快进、是否存在语法冲突，由确定性 Git 算法给出事实结论；Agent 仅在用户主动唤起时参与复杂成因解释与操作方案准备，不可用 AI 猜测混淆事实。
3. **极简专注，拒绝过度设计**：
   - 首页不堆砌筛选搜索栏、统计数字与操作栏；
   - 任务详情页去除复杂的批量勾选、重复标题与控制按钮；
   - 核心任务左侧只负责切换子任务，右侧只呈现简要结论与真实 Git 证据链接。
4. **Local-first 与可选的第三方 Agent**：
   Workdesk 的 Git 检测、证据查看和任务存储在本地完成。用户可以自行配置第三方 OpenAPI，并选择是否使用 Agent。用户主动发起 Agent 请求时，本次请求所需的任务上下文会发送至用户选定的提供方，数据处理遵循该提供方的政策。此例外在首次使用 Agent 时说明。
5. **轻量分享（Portable Check）而非中心化协作**：
   支持导出“可移植检查配方（Recipe）”，由接收人在自己本地重新验证，不共享本地任务数据库。

## 4. 信息架构与路由规范

### 4.1 页面层次与路由映射

```text
Yggit 全局顶栏 (持久保留: Logo / 项目切换器 / Local·Edge / 设置)
  │
  ├── /no-project                       未接入任何仓库时的引导页 (维持现状)
  ├── /workdesk                         工作台首页 (已有仓库时的默认入口)
  │     └── 4 列自适应工作看板 (分支维护 / 合并集成 / 研发规范 / 代码审查)
  │
  ├── /workdesk/tasks/:taskId           聚合工作卡片详情
  │     └── 左侧子任务清单 + 右侧选中项证据
  │
  ├── /workdesk/tasks/:taskId/items/:itemId  指定子任务详情 (与上同一页面组件，同步 URL)
  │
  ├── /import#data=... 或 /import        Portable Check 导入预览与本地重检
  │
  └── 现有 Git 工作区 (深链跳入)
        ├── Commit Graph / Commit Detail
        └── File Content / Diff Viewer
```

### 4.2 路由与状态恢复规范

- **真实 URL 驱动**：`/workdesk/tasks/:taskId` 与 `/workdesk/tasks/:taskId/items/:itemId` 具备独立、稳定可访问的 URL，支持浏览器直接刷新、前进、后退与复制。
- **返回恢复**：从子任务页返回看板时，自动恢复看板的滚动位置与视口状态。
- **失效容错**：若 URL 中的 `taskId` 已被移除或失效，展示友好提示与“返回工作台”按钮，不出现白屏。
- **顶栏项目切换器联动**：
  - 当处于 `/workdesk` 看板或任务页时，顶栏项目切换器高亮显示为 `⚑ 工作台 ⌄`，下拉菜单支持切换至特定单一仓库视图或直接添加新项目；
  - 从任务详情打开提交或文件证据时，顶栏项目切换器同步为目标仓库。浏览器返回时恢复原子项。

### 4.3 国际化多语言支持 (i18n)

遵循 Yggit 平台全局国际化规范（`lib/i18n/`），所有面向用户的文案必须提取至专属词条模块（`lib/i18n/messages/parts/workdesk/`）：

- 支持简体中文（`zh`）、繁体中文（`cht`）与英文（`en`）；
- 覆盖四大分类标题、卡片范围文案（如 `{count} 个项目` / `{count} projects`）、子任务状态徽章（“可处理”/“需核查”/“需处理”）、证据说明与移除弹窗。禁止在代码中硬编码中文字符串。

## 5. 看板与任务核心功能

### 5.1 首页看板：四类基础工作场景

本期覆盖桌面端。首页采用四列等宽网格，随桌面窗口宽度压缩。

1. **分支维护 (`branch`)**：
   - 默认分支同步检查（远端超前、本地落后、安全快进判定）；
   - 打开工作台先显示最近一次检查及其时间。可见时定时刷新，P0 默认间隔为 5 分钟。Local 按仓库刷新相关上游，Edge 在可访问远端时只读核对分支引用。远端状态或祖先证据不足时标记「待核查」；
   - 多 Worktree 与长期未同步开发分支健康度检查；
   - 远程引用清理与分支分叉预警。
2. **合并集成 (`merge`)**（P0 后按需检查）：
   - 单分支合并预演（Preflight Check）；
   - 跨分支集成结果核对。固定开发分支 A、B 和环境分支 C、D 的检查快照，在 A、B 的相关变更范围内比较两侧结果，呈现一致、缺失或有差异的证据。D 的基线变化和无关提交单独展示；
   - 有可比证据时，展示 C、D 上对应冲突片段的最终内容。结果有差异时提供并排 Diff，缺少可比证据时标记「待核查」，D 尚未集成时标记「待集成」。需要追溯时跳转到 `/git`，在 SOLO 模式查看合并节点；
   - 语义风险提示与交叠修改预警。
3. **研发规范 (`standard`)**：
   - 分支命名与生命周期规范核查；
   - 预设代码提交规范与受保护路径修改校验。
4. **代码审查 (`review`)**：
   - P0 后支持按需复核冲突解决结果（对比解决后的提交与当前最新目标分支）；
   - 跨分支变更影响范围查验；
   - 人工 Review 关注项跟踪。

> **分类规则策略**：
>
> - MVP 阶段采用**确定性规则映射**（Rule-based），按检查类型归入对应列；
> - 进阶阶段支持 Agent 提议调整分类或新增自定义类别，但须经用户确认并保留来源标示（`rule` / `agent` / `user`）。

### 5.2 紧凑工作卡片 (Work Card)

- 卡片采用清新紧凑视觉：包含工作图标、工作名称（最多两行）、影响范围摘要（例如 `5 个项目`、`3 个项目 · 4 Worktrees`）以及右侧进入箭头 `›`。
- **无多选复选框**：首页卡片为直接入口，单击整卡即以轻量转场进入任务页。
- 卡片不堆砌冗余操作按钮，保持桌面视线聚焦。

### 5.3 任务详情页：极简左清单 + 右证据

从桌面端看板点击卡片后进入任务详情，采用**左侧任务清单 / 右侧证据详情**布局。

1. **左侧任务清单 (Task Navigation)**：
   - **聚合任务（多子任务）**：按仓库名称（Project）对子任务分组，展示子任务名称、状态圆点（绿色通过 / 黄色需核查 / 红色存在风险）与极简摘要。点击即刻更新右侧内容并同步浏览器 URL。
   - **单任务（单个子任务）**：左侧展示极简当前任务标记，不呈现空洞的列表树。
2. **右侧 Git 证据详情 (Git Evidence Detail)**：
   - **头部**：项目名称、分支/子任务名称与状态徽标；
   - **检查结论**：一句话简要说明（如“远端领先，可安全快进”或“预发分支的冲突解决结果与测试分支有差异”）；
   - **可导航 Git 证据列表**：
     - **相关 Commit**：跳转至当前仓库的目标提交；
     - **相关文件 / Diff**：已知提交时在该提交下打开文件，沿用 Git 工作区现有的 Diff 基准。仅有路径时展示路径；
   - **冲突处理**：由用户实际发起的合并流程呈现冲突。P0 的定时巡检只更新检查结果和卡片状态，三方冲突深链及跨分支冲突结果对比延后。
   - **底部辅助区**支持「从工作台移除卡片」，并提供 10 秒的「撤销」入口以处理误操作。移除只隐藏本次打开工作台期间的当前检查结果。结果有实质变化或重新打开工作台时，按最新检查结果生成卡片。
3. **交互精简原则**：
   详情页内**不放置**“重新检查”、“批量同步”、“批量勾选”、“交给 Agent”等沉重操作按钮；需要深入排查或执行时，用户通过已有的底部 Agent 药丸交互。

## 6. Agent 深度协同与操作安全

1. **复用既有组件**：
   沿用 Yggit 底部居中的浮动药丸（Agent Pill）与右侧抽屉式聊天侧栏（Agent Sidebar），不新建第二套对话框。
2. **上下文自动注入**：
   展开 Agent 侧栏时在本地载入当前任务、子任务、关联仓库和证据上下文。用户主动发起 Agent 请求时附带本次请求所需的上下文，无需手动复制粘贴。
3. **只读优先与授权守卫**：
   - Agent 默认进行只读查询、证据汇总与方案准备。涉及工作树、本地分支或远端引用的写入时，先实时重查，再展示具体的行动清单供用户批准。
   - 用户批准后，本地执行端在每项写入前再次校验仓库、工作树、目标引用和提交 OID，只应用已批准的变更。条件变化且仍需写入时，展示更新后的方案并重新取得批准。
4. **行动执行闭环（以批量快进为例）**：
   - 用户通过 Agent 请求同步，系统重查相关子项，只有检查结果仍允许快进的项目才进入确认清单。
   - 执行期间发现状态竞争时，自动刷新并重查一次。问题已解决时，子项自动移出待办，整张卡无待办时从看板收起。同一问题的执行条件仍成立时继续执行，条件变化时更新原子项并等待再次批准。问题性质变化时关闭原子项并关联新子项。状态仍无法确认时保留为「待核查」，批次继续处理其他项目。
   - 执行后以重检结果回写卡片与 Finding 状态。各类刷新和写入的边界见[技术架构 §6.2](../technical/yggit-workdesk-architecture.md#62-写操作执行守卫)。

## 7. Portable Check (可移植检查分享)

### 7.1 定位与边界

- **个人版开箱可用**：无需注册后端账号或部署专用协同服务器；
- **配方内容**只包含仓库匹配指纹、必要的分支名和检查规则参数。仓库域名、组路径、项目名、别名、源码、Diff 和本地绝对路径留在各自设备上。导出前展示会随配方分享的分支等字段。
- **接收端独立验证**。接收方可以在配对校验通过后查看已匹配的本地项目，并主动运行检查获得本地结果。分享方逐项基准、原结论和跨基准对比列为后续增强。

### 7.2 接收流程

1. **不可信载荷校验**：解析 URL Fragment（`#data=...`）或上传的 `.yggit-check` 文件，经过严格 JSON Schema 结构校验；
2. **本地项目匹配**。在接收端根据本地项目的实际远端计算匹配指纹。唯一命中时自动绑定。多个 clone 或 Worktree 命中时，由用户在通过校验的目录中选择。
3. **仓库不匹配**时保留为「待关联」，添加正确仓库后重新校验。仅允许对匹配通过的仓库执行检查，其他仓库可等补齐后再验证。分支缺失或检查规则不可用时，明确提示该项无法执行。

## 8. MVP 交付范围与验收准则

### 8.1 交付清单 (P0)

- [ ] **Workdesk 看板骨架**：接入 4 个基础分类，自适应网格布局，紧凑卡片渲染；
- [ ] **端到端典型场景**：
  - 默认分支定时刷新与批量同步检查（判定可快进 / 脏工作区 / 分叉，证据不足时待核查）；
  - 多 Worktree 与并行开发分支健康检查；
- [ ] **左右分栏任务详情**：左侧按项目分组，右侧支持 Commit 和文件证据跳转，浏览器返回可恢复原子项；
- [ ] **Agent 药丸上下文连通**：任务页唤起 Agent 时自动绑定任务元数据；
- [ ] **本地持久化与移除**。保存本地检查结果，支持本次打开工作台期间移除卡片和 10 秒撤销。
- [ ] **Portable Check 基础导入**：支持链接导入预览、本地仓库匹配与已匹配项验证。

### 8.2 核心验收场景

1. **15 项目聚合卡片**：工作台可见时，定时刷新后更新「同步默认分支」聚合卡片与检查时间。远端或祖先证据不足的项目显示「待核查」，刷新仅更新看板；
2. **证据直达无损跳转**：点击任务详情里的 Commit 或文件路径，平滑定位到原有 Git 工作区，点击浏览器返回可准确复原任务视图；
3. **Agent 药丸免输入**：进入某子任务后展开 Agent，主动发送请求时携带当前任务所需的上下文。首次使用可查看发送范围和第三方提供方；
4. **并发下的 Agent 写入**：同批次模拟已由他人解决、仍能执行、目标变动、转为分叉和状态不明，逐项检查自动移出、继续、重新确认、切换子项和暂停。写入结果须与用户批准的目标 OID 一致；
5. **便携分享接收**。打开分享链接后，可查看匹配通过的本地仓库并启动检查。选择同名但不同远端的仓库时，校验失败且该项保持待关联。
6. **误移除恢复**。移除卡片后 10 秒内可撤销，同一结果的定时刷新保持原有隐藏状态，重新打开工作台按最新检查结果生成卡片。
