## 1. 产品背景与定位

### 1.1 现状与定位辨析

在现代化研发中，开发者频繁面对跨仓库、多分支、多 Worktree 的复杂状态：

- 版本发布后，十几个关联微服务或前后端项目的默认分支需要同步；
- 多个 Feature 分支同时推进，各分支落后于主干、部分存在潜在冲突；
- 多个 Feature 单独向主干合并均无冲突，但组合集成时产生逻辑或文本冲突；
- 测试分支（`test`）存在未经主线流程审核的临时提交，存在发布遗漏隐患。

**Yggit Workdesk 的核心定位**：

- **不重复** GitHub / GitLab 的 Web PR/MR 审批流、工时管理或 CI/CD 统计仪表盘；
- **不重复** Jira / Trello 式的通用敏捷项目看板；
- **专注 Git 真实研发场景**：通过确定性的程序化 Git 规则检测，自动聚类为**具体、可执行的 Git 任务卡片**；
- **极简下钻与证据定位**：用户在紧凑看板中概览卡片，点击即可在左右分栏中查验提交、文件差异与冲突分析证据，并按需调起现有的 Yggit Git Agent 辅助决策。

```text
┌─────────────────┐     ┌───────────────────┐     ┌──────────────────┐     ┌───────────────────────┐
│ Git 状态与规则检测 │ ──> │ 智能聚类成工作卡片   │ ──> │ 极简下钻查验证据   │ ──> │ 定位 Git / Agent 协作 │
│ (确定性程序驱动)    │     │ (4个基础工作分类)   │     │ (左清单 / 右证据) │     │ (一键直达或药丸唤起)   │
└─────────────────┘     └───────────────────┘     └──────────────────┘     └───────────────────────┘
```

## 2. 核心设计原则

1. **一卡片 = 一件具体工作**：
   不把几百条原子检测异常（Findings）平铺给用户。依据研发目标（如“同步默认分支”、“多分支组合预演”）聚合为卡片；每个卡片聚合多项目、多分支、多 Worktree 的子任务。
2. **程序负责可靠发现，Agent 负责理解与协助**：
   分支是否分叉、能否快进、是否存在语法冲突，由确定性 Git 算法给出事实结论；Agent 仅在用户主动唤起时参与复杂成因解释与操作方案准备，不可用 AI 猜测混淆事实。
3. **极简专注，拒绝过度设计**：
   - 首页不堆砌筛选搜索栏、统计数字与操作栏；
   - 任务详情页去除复杂的批量勾选、重复标题与控制按钮；
   - 核心任务左侧只负责切换子任务，右侧只呈现简要结论与真实 Git 证据链接。
4. **Local-first 与数据零出站**：
   代码、Git 历史与完整分析结果全部保留在本地（Local 文件系统或 Edge 浏览器 IndexedDB）；云端不保存任何源码与私有信息。
5. **轻量分享（Portable Check）而非中心化协作**：
   支持导出“可移植检查配方（Recipe）”，由接收人在自己本地重新验证，不共享本地任务数据库。

## 4. 信息架构与路由规范

### 4.1 页面层次与路由映射

```text
Yggit 全局顶栏 (持久保留: Logo / 项目切换器 / Local·Edge / 设置)
  │
  ├── /no-project                       未接入任何仓库时的引导页 (维持现状)
  ├── /workdesk                         工作台首页 (已有仓库时的默认入口)
  │     └── 4 列自适应工作看板 (分支维护 / 合并集成 / 研发规范 / 代码审查)
  │
  ├── /workdesk/tasks/:taskId           聚合工作卡片详情
  │     └── 左侧子任务清单 + 右侧选中项证据
  │
  ├── /workdesk/tasks/:taskId/items/:itemId  指定子任务详情 (与上同一页面组件，同步 URL)
  │
  ├── /import#data=... 或 /import        Portable Check 导入预览与本地重检
  │
  └── 现有 Git 工作区 (深链跳入)
        ├── /git/[...slug]?commit=...   Commit Graph / Commit Detail
        ├── /git/[...slug]?file=...     File Content / Diff Viewer
        └── /git/[...slug]?conflict=... 3-Way 冲突分析器
```

### 4.2 路由与状态恢复规范

- **真实 URL 驱动**：`/workdesk/tasks/:taskId` 与 `/workdesk/tasks/:taskId/items/:itemId` 具备独立、稳定可访问的 URL，支持浏览器直接刷新、前进、后退与复制。
- **返回恢复**：从子任务页返回看板时，自动恢复看板的滚动位置。
- **失效容错**：若 URL 中的 `taskId` 已被移除或失效，展示友好提示与“返回工作台”按钮，不出现白屏。

## 5. 看板与任务核心功能

### 5.1 首页看板：四类基础工作场景

首页桌面端优先以**四列等宽自适应网格**展示，屏幕自适应压缩，优先一屏展示，窄屏（小于 720px）自适应折叠为双列：

1. **分支维护 (`branch`)**：
   - 默认分支同步检查（远端超前、本地落后、安全快进判定）；
   - 多 Worktree 与长期未同步开发分支健康度检查；
   - 远程引用清理与分支分叉预警。
2. **合并集成 (`merge`)**：
   - 单分支合并预演（Preflight Check）；
   - 手选多分支顺序集成模拟与冲突步骤定位；
   - 语义风险提示与交叠修改预警。
3. **研发规范 (`standard`)**：
   - 测试分支（`test`）与发布分支（`release/*`）非正规提交追踪；
   - 分支命名与生命周期规范核查；
   - 预设代码提交规范与受保护路径修改校验。
4. **代码审查 (`review`)**：
   - 冲突解决结果复核（对比解决后的提交与当前最新目标分支）；
   - 跨分支变更影响范围查验；
   - 人工 Review 关注项跟踪。

> **分类规则策略**：
>
> - MVP 阶段采用**确定性规则映射**（Rule-based），按检查类型归入对应列；
> - 进阶阶段支持 Agent 提议调整分类或新增自定义类别，但须经用户确认并保留来源标示（`rule` / `agent` / `user`）。

### 5.2 紧凑工作卡片 (Work Card)

- 卡片采用清新紧凑视觉：包含工作图标、工作名称（最多两行）、影响范围摘要（例如 `5 个项目`、`3 个项目 · 4 Worktrees`）以及右侧进入箭头 `›`。
- **无多选复选框**：首页卡片为直接入口，单击整卡即以轻量转场进入任务页。
- 卡片不堆砌冗余操作按钮，保持桌面视线聚焦。

### 5.3 任务详情页：极简左清单 + 右证据

从看板点击卡片后进入任务详情，采用**左侧任务清单 / 右侧证据详情**的固定布局：

1. **左侧任务清单 (Task Navigation)**：
   - **聚合任务（多子任务）**：按仓库名称（Project）对子任务分组，展示子任务名称、状态圆点（绿色通过 / 黄色需核查 / 红色存在风险）与极简摘要。点击即刻更新右侧内容并同步浏览器 URL。
   - **单任务（单个子任务）**：左侧展示极简当前任务标记，不呈现空洞的列表树。
2. **右侧 Git 证据详情 (Git Evidence Detail)**：
   - **头部**：项目名称、分支/子任务名称与状态徽标；
   - **检查结论**：一句话简要说明（如“远程领先，可安全快进”或“合并到 master 的预演存在冲突”）；
   - **可导航 Git 证据列表**：
     - **相关 Commit**：点击直接跳转并高亮当前仓库的 Commit Graph；
     - **相关文件 / Diff**：点击直接跳转至该文件的 Side-by-side Diff 查看器；
     - **冲突与预演**：存在冲突时，点击一键跳转至 Yggit 现有的冲突 3-way 分析器；
   - **底部辅助区**：轻量提示“需要协助时，使用下方 Git Agent 药丸”；提供低频 `···` 下拉菜单（支持“从工作台移除卡片”）。
3. **交互精简原则**：
   详情页内**不放置**“重新检查”、“批量同步”、“批量勾选”、“交给 Agent”等沉重操作按钮；需要深入排查或执行时，用户通过已有的底部 Agent 药丸交互。

## 6. Agent 深度协同与操作安全

1. **复用既有组件**：
   沿用 Yggit 底部居中的浮动药丸（Agent Pill）与右侧抽屉式聊天侧栏（Agent Sidebar），不新建第二套对话框。
2. **上下文自动注入**：
   当在任务详情页中点击底部药丸或展开 Agent 侧栏时，系统自动附带当前任务 ID、子任务 ID、关联仓库、分支名称与证据 OID，无需用户手动复制粘贴。
3. **只读优先与授权守卫**：
   - Agent 默认仅执行无害的只读查询、证据汇总与建议方案准备；
   - 涉及任何可能改变工作区、分支指向或远端引用的写操作（如快进合并、切换分支、清理引用），必须在对话中向用户出具具体的行动清单并取得显式批准。
   - 执行前再次校验当前工作区状态与 Commit OID，杜绝并发变动造成数据损坏。

## 7. Portable Check (可移植检查分享)

### 7.1 定位与边界

- **个人版开箱可用**：无需注册后端账号或部署专用协同服务器；
- **分享的是配方，不是数据库**：分享内容仅包含待检查仓库的远程标识（Remote Identity）、分支名、基准 Commit OID 与检查规则参数，**不上传源码、不上传 Diff、不包含本地绝对路径**；
- **接收端独立验证**：接收方在自己的设备上运行本地检查，生成属于接收方自己的 Findings，并与分享者原结论并列比对展示。

### 7.2 接收流程

1. **不可信载荷校验**：解析 URL Fragment（`#data=...`）或上传的 `.yggit-check` 文件，经过严格 JSON Schema 结构校验；
2. **本地项目自动匹配**：依据正规化的远程仓库 URL 或稳定 Identity 匹配接收方本地已有项目；
3. **支持部分验证**：如分享包含 4 个项目，接收方仅有其中 1 个，允许直接验证已匹配项目，未关联项目标注为“待关联”，不阻塞体验；
4. **基准差异提示**：若接收方本地分支的最新 Commit 与分享时的基准 OID 不一致，明确标示“不同基准”，客观呈现本地实时检查结果。

## 8. MVP 交付范围与验收准则

### 8.1 交付清单 (P0)

- [ ] **Workdesk 看板骨架**：接入 4 个基础分类，自适应网格布局，紧凑卡片渲染；
- [ ] **端到端典型场景**：
  - 默认分支批量同步检查（判定可快进 / 脏工作区 / 分叉）；
  - 多 Worktree 与并行开发分支健康检查；
- [ ] **左右分栏任务详情**：左侧项目分组子任务列表，右侧 Commit / 文件 / 冲突深链跳转；
- [ ] **Agent 药丸上下文连通**：任务页唤起 Agent 时自动绑定任务元数据；
- [ ] **本地持久化与移除**：支持从工作台移除已解决或忽略的卡片，状态持久保存；
- [ ] **Portable Check 基础导入**：支持链接导入预览、本地仓库匹配与已匹配项验证。

### 8.2 核心验收场景

1. **15 项目聚合卡片**：本地配置多个仓库，远端更新后，首页仅呈现 1 张“同步默认分支”聚合卡片，点进后能清晰区分安全与不安全项目；
2. **证据直达无损跳转**：点击任务详情里的 Commit 或文件路径，平滑定位到原有 Git 工作区，点击浏览器返回可准确复原任务视图；
3. **Agent 药丸免输入**：进入某子任务后展开 Agent，Agent 能直接感知当前任务及关联仓库，无需重复交代背景；
4. **便携分享接收**：将生成的检查链接发给仅有部分仓库的浏览器，能正确展示已匹配与未匹配列表，并能一键启动本地检测。
