# Yggit Agent — UX 交互设计方案

> 文档类型：UX 交互设计规范  
> 版本：V1.1（已整合评审优化项）  
> 状态：方案已对齐，待研发实施  
> 所属模块：Agent / Git 工作区 / 上下文管理 / 布局系统  
> 设计原则：轻量入口、就地速答、无损停靠、上下文显式可见、Git 内容优先、零存储安全

---

## 1. 设计背景

Yggit 是一个面向 Git 历史浏览、分支分析、代码检索和人工 Code Review 的现代化 Git 可视化工作台。

系统在页面底部居中增加一个小药丸形态的 Agent 交互入口，允许用户随时使用自然语言查询 Git 仓库状态与拓扑关系。

### 典型问题与操作诉求

- 这个 Merge 引入了哪些提交？
- 谁把 `test` 合并进了 `feature/order`？
- 这个函数以前被哪些 Commit 修改过？
- 这次变更影响哪些调用方？
- 从哪个节点重新 Cherry-pick 比较合适？
- 这个分支是否误合入了测试分支？

与普通网页聊天应用不同，Yggit Agent 必须深度结合用户当前正在查看的 Git 仓库、分支、Commit、Diff 和代码行范围进行上下文协同分析。

### 1.1 传统设计痛点

1. **遮挡工作区**：底部悬浮的大型对话弹窗会严重遮挡 Git Graph 或代码 Diff。
2. **长对话挤压代码**：长篇对话占据过多屏幕，无法一边读代码一边读分析。
3. **上下文黑盒**：用户无法明确感知 Agent 当前是基于哪个 Commit/分支在回答。
4. **证据无法落地**：Agent 回答中出现的 Commit Hash 或文件路径无法直接在界面联动高亮。
5. **轻问答过度打扰**：简单的单步查询（如“查查作者是谁”）如果强制改变屏幕分栏布局，会造成剧烈的视觉震荡。

### 1.2 设计目标

构建统一的 Agent 交互系统：

$$\textbf{底部轻量小药丸} \longrightarrow \textbf{快速输入与就地速答} \longrightarrow \textbf{可停靠深度工作区 (Dock Workspace)} + \textbf{显式上下文管理}$$

- **轻量不侵占**：默认状态仅占极小面积，随时可用，随手即关；
- **轻重分离**：简单查询就地出卡片，不强制重绘屏幕；深度排查与长对话平滑停靠到侧边或底部；
- **上下文透明**：自动跟随（Following）与手动固定（Pinned）双轨驱动；
- **证据链联动**：回答中的 Commit、分支、代码行一键直达生命树高亮；
- **零存储安全**：凭证仅驻留内存，关闭网页彻底销毁，绝不落盘。

## 2. 核心交互原则

### 2.1 Git 内容优先 (Git Content-First)

Git Graph、Commit Diff 和代码是核心主体。Agent 是辅助工作区，不应长期以浮层形式遮挡核心内容，优先采用非遮挡式的**分栏停靠（Docking）**。

### 2.2 轻重分流，按需停靠 (Adaptive Escalation)

- **轻问答（1 轮速查）**：直接在浮层内输出富交互卡片（带高亮按钮与复制链接），无需破坏全屏布局；
- **深度排查（多轮对话/大段分析）**：一键升级或按需展开为停靠工作区（Dock Panel），与代码并排查看。

### 2.3 单一会话，多种布局 (Seamless Layout Switching)

同一段 Agent 对话可在“快速浮层”、“右侧停靠”与“底部停靠”之间无缝切换，切换时不丢失草稿、不中断分析、不刷新上下文。

### 2.4 上下文显式可见与双轨制 (Explicit Dual-Track Context)

引用的仓库、分支、Commit 或代码范围必须可视化为 Context Chips，支持查看、固定、移除与跳转。

### 2.5 零存储安全底线 (Zero-Storage In-Memory)

布局偏好（面板宽度、停靠模式）允许持久化；但敏感凭证（OpenAPI Key、自备 Proxy 地址）严格限制在 React 运行时内存中，刷新即毁，杜绝共享设备泄露。

## 3. Agent 四种界面形态

```text
                                  点击药丸
               Collapsed (小药丸) ──────────> Quick Input (快速输入)
                       ▲                            │
                       │                            │ 轻问答：就地出卡片
                       │                            ▼
                       │                    In-Place Card (就地速答)
                       │                            │
                       │ 点击收起                   │ 深入探讨 / 点击 ⇱ / 多轮对话
                       │                            ▼
                       │                    Docked Workspace
                       │                   ┌────────┴────────┐
                       │                   ▼                 ▼
                       └────────────── Dock Right       Dock Bottom
```

---

### 3.1 Collapsed — 小药丸状态 (Floating Pill)

默认常驻在页面底部水平居中位置。

```text
┌───────────────────────────────────────────────┐
│                                               │
│              Git Graph / Diff                 │
│                                               │
│          ╭────────────────────────╮           │
│          │ ✨ 询问 Yggit Agent... │           │
│          ╰────────────────────────╯           │
└───────────────────────────────────────────────┘
```

**交互规范**

- **尺寸**：高度 `40px`，宽度 `260–300px`，圆角 `full (999px)`，底部边距 `bottom: 20px`；
- **视觉层级**：`bg-[var(--panel)]/85` 搭配 `backdrop-blur-md`，细腻边框，阴影 `shadow-md`；
- **全屏阅读避让**：在全屏浏览 Diff 且无鼠标聚焦时保持半透明通透度（`opacity-80`），鼠标悬停（Hover）时恢复 100%；
- **状态感知**：未激活时显示占位文案；分析进行中显示微动轻量进度气泡（如 `正在分析 Git 历史…`）；
- **操作响应**：点击药丸或按下全局快捷键 `⌘/Ctrl + J` 立即展开进入快速输入。

---

### 3.2 Quick Input — 快速输入与就地速答

点击药丸后，在底部居中向上平滑展开紧凑输入面板。

```text
       ╭──────────────────────────────────────────────╮
       │ ✨ Yggit Agent                         ⇱  −  │
       ├──────────────────────────────────────────────┤
       │ 📎 [feat/order] [8f3a2c] [+ 添加]            │
       │                                              │
       │ 询问当前 Git 历史或输入指令...               │
       │                                              │
       │ ───────────────────────────────────────────  │
       │ [ 📅 今日合并到 TEST ]  [ 🌿 分支包含检测 ]  │
       │                                     ↑ 发送   │
       ╰──────────────────────────────────────────────╯
```

**核心优化：轻重两级响应模式**

1. **轻量问答（In-Place Response Card）**：
   - 用户提问后，若属于单步工具调用（如“查作者”、“包含判定”、“今日合并”），**直接在当前浮层内部渲染结构化结果卡片**，无需强制重绘全屏工作区！
   - 卡片内提供直接动作：`[在生命树中定位]`、`[🔗 复制分享链接]`、`[⇱ 停靠深入讨论]`。
2. **深度对话（Escalate to Dock）**：
   - 面板右上角显式提供 **`[ ⇱ 停靠到侧边 ]`** 按钮；
   - 当用户在卡片后继续追问、或进行代码逻辑/跨文件重构分析时，面板平滑过渡到停靠工作区。

---

### 3.3 Dock Right — 右侧停靠工作区

桌面大屏下的主力深度对话形态，与 Git Graph 并排展示。

```text
┌────────────────────────────┬────────────────────────┐
│                            │ ✨ Yggit Agent     ▤ − │
│                            ├────────────────────────┤
│       Git 工作区            │ 当前引用               │
│                            │ [feat/order] [8f3a2c]  │
│       Graph / Diff         │                        │
│                            │ ────────────────────── │
│                            │ 💬 对话流与证据卡片    │
│                            │                        │
│                            │ 8f3a2c (Merge Commit)  │
│                            │ 包含来自 test 的 3 节点│
│                            │ [在图谱中定位]         │
│                            ├────────────────────────┤
│                            │ ┌────────────────────┐ │
│                            │ │ 继续追问...        │ │
│                            │ └────────────────────┘ │
└────────────────────────────┴────────────────────────┘
```

**核心优化：与右侧已有 `GitCommitPanel` 的排布协调**

- **空间冲突规避**：当前 Yggit 右侧默认承载选中 Commit 的文件列表与变更。若屏幕总宽不足 `1440px`，直接在最右侧追加第 4 栏会导致 GitGraph 被挤压到无法阅读。
- **解决方案**：
  1. **右侧 Tab 融合模式**：在右侧面板顶部引入分栏选项：`[ 📁 变更文件 (12) ] | [ ✨ Agent 辅助分析 ]`，支持一键切换或上下并排；
  2. **智能降级建议**：视口宽度 `< 1440px` 时，系统默认推荐并记忆使用 **`Dock Bottom`（底部停靠）**，确保横向代码阅读空间完整。

---

### 3.4 Dock Bottom — 底部停靠工作区

适合全屏查看双栏 Diff、代码阅读或中小屏幕尺寸。

```text
┌─────────────────────────────────────────────────────┐
│                                                     │
│                 Git Diff (双栏代码阅读)             │
│                                                     │
├─────────────────────────────────────────────────────┤
│ ✨ Yggit Agent                               ▧  − × │
│  诊断结果：发现 2 个可疑合入点，涉及以下变更文件... │
│  ┌───────────────────────────────────────────────┐  │
│  │ 继续追问代码逻辑...                           │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

**交互规范**

- 位于主视图底部，高度默认 `280px`（最小 `200px`，最大不超过视口高度的 50%）；
- 顶部提供水平拖动条（Splitter）调整高度；
- 完美解决双栏 Diff 横向宽度受挤压的痛点。

## 4. 面板状态与转换矩阵

### 4.1 状态定义

```typescript
export type AgentPanelMode =
  | 'collapsed' // 底部小药丸
  | 'quick-input' // 快速输入与就地速答浮层
  | 'dock-right' // 右侧停靠工作区
  | 'dock-bottom' // 底部停靠工作区
```

### 4.2 触发动作映射表

| 用户操作                            | 当前状态      | 迁移后状态                      | 界面行为                                               |
| ----------------------------------- | ------------- | ------------------------------- | ------------------------------------------------------ |
| 点击小药丸 / 按下 `⌘+J`             | `collapsed`   | `quick-input`                   | 药丸向上平滑展开，输入框自动获得焦点                   |
| 提问简单单步问题（查作者/分支判断） | `quick-input` | `quick-input` (保持)            | **就地渲染结果卡片**，不重绘全屏分栏，支持一键高亮图谱 |
| 点击卡片右上角 `⇱` / 继续长对话     | `quick-input` | `dock-right` (或 `dock-bottom`) | 平滑拉出分栏，收起浮层，对话无缝迁移至停靠工作区       |
| 点击停靠面板顶部 `▤ / ▧`            | `dock-right`  | `dock-bottom`                   | 左右并排切换为上下分栏，消息与滚动位置无损保持         |
| 点击收起按钮 `−` / 按下 `Esc`       | 任意展开态    | `collapsed`                     | 面板收起恢复全屏 Git 内容，底部还原为小药丸            |
| 再次点击小药丸                      | `collapsed`   | 上次使用的活跃状态              | 恢复历史消息、上下文快照与草稿，不创建重复会话         |

## 5. Git 上下文管理规范

### 5.1 双轨上下文架构

```text
Git Context Manager
├── 自动跟随上下文 (Following - 动态)
│   ├── 当前仓库 (Current Repo)
│   ├── 当前分支 (Active Branch)
│   └── 当前选中提交/Diff 文件 (Focused Commit & Diff)
│
└── 手动固定上下文 (Pinned - 静态常驻)
    ├── 用户主动 Pin 的分支 (如 "test")
    ├── 指定对比的 Base Commit
    └── 选中的关键代码片段 (#L42-L68)
```

### 5.2 Context Chips 交互规范

- **展示形式**：输入框上方紧凑展示标签胶囊：
  - `[ 📌 target: test ]`（固定上下文，带 Pin 标识，带 `×` 移除按钮）
  - `[ 📎 HEAD: 8f3a2c ]`（自动跟随上下文，随页面点击自动变更）
- **右键菜单集成**：
  - 在 GitGraph 提交节点或 Diff 代码行右键菜单新增：
    - `添加到 Agent 上下文`（仅注入引用，不打扰当前页面）
    - `询问 Agent`（注入引用并立即唤起快速输入框）

### 5.3 跨页面与跨仓库安全边界

- **Commit 跳转**：从 Commit A 切到 Commit B 时，自动上下文更新为 B，已 Pin 的 Commit A 保留。**历史消息的上下文快照永久锁定**，严禁将历史回答误匹配给新 Commit。
- **仓库切换**：切换 Repository 时不静默清空会话；跨仓库引用在 Chip 上显式标明 `[repo: billing]`，避免跨仓指代混淆。

## 6. 回答证据链与 Git 工作区联动 (Evidence Navigation)

| 证据类型         | Agent 输出形式                     | 点击响应行为                                                                              |
| ---------------- | ---------------------------------- | ----------------------------------------------------------------------------------------- |
| **Commit 引用**  | `8f3a2c — Merge test into feature` | GitGraph 自动平滑滚动并居中该节点，高亮光晕，**其余无关分支降低至 35% 不透明度**          |
| **文件与行号**   | `src/order/service.ts:42-68`       | 自动打开右侧 Diff 面板，跳转并高亮对应行范围代码                                          |
| **分支污染诊断** | `检测到包含 test 分支的 3 个节点`  | 触发 `setLineageHashes`，图谱加粗绘制污染拓扑泳道，卡片呈现 **`[ 🔗 复制排查分享链接 ]`** |

## 7. 持久化与安全性严格约定

### 7.1 允许持久化（通过 Yggit 已有的 `useGitUiPref` 本地存储）

- 用户最后一次使用的停靠模式（`dock-right` 或 `dock-bottom`）；
- 用户拖动调整后的侧栏宽度（`rightWidth`）与底栏高度（`bottomHeight`）；
- 输入框未发送时的临时文本草稿（Draft）。

### 7.2 严格零持久化（Zero-Storage In-Memory Only）

- **第三方 OpenAPI Key / Token**：必须仅存于 React State，**严禁落盘至 `localStorage`、`IndexedDB`、Cookie 或后端服务器**；
- 页面刷新、Tab 关闭或点击“清空凭证”，内存立即抹除；
- 无状态深链接（Deep Link）将诊断链路和 Commit Hash 编码在 URL Query 中，实现接收方点开即还原，无需任何云端数据库。

## 8. 实施分期 (Roadmap)

### Phase 1：MVP 核心链路 (P0)

- 底部悬浮小药丸组件 (`GitAgentBar.tsx`)，支持 `⌘+J` / 点击唤出；
- 快速输入面板与零存储配置插槽；
- 简单查询的**就地速答卡片**（今日合并、提交作者查询、分支包含检测）；
- 诊断结果联动主图谱高亮与弱化（`Lineage Highlight & Dimming`）；
- 无状态深链接复制与 URL 逆解析还原。

### Phase 2：深度停靠与上下文增强 (P1)

- `Dock Right` 与 `Dock Bottom` 停靠分栏与可拖拽 Splitter；
- 右侧面板与 `GitCommitPanel` 的 Tab 融合切换；
- 显式 Context Chips 交互（自动跟随 + 手动 Pin）；
- 右键菜单快捷注入上下文。

### Phase 3：长效体验与 CR 辅助 (P2)

- 多轮深度追问流式展示；
- 代码选区一键发往 Agent；
- Local 模式自动探测并桥接本机已登录的 CLI 订阅（Claude Code / Codex / Antigravity）。
