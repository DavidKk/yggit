# Yggit 世界树底部溪流动态效果技术方案

**版本：** v1.0  
**适用平台：** PC / 移动端 Web  
**推荐技术：** PixiJS + WebGL Shader + Flow Map  
**设计目标：** 高品质、自然流动、稳定运行、保留原始画风

---

## 1. 需求背景

Yggit 官方主页采用世界树与山谷溪流组成的幻想风格场景。

目前溪流属于静态背景图片，虽然具有水面反射、波纹、石头及环境光照等细节，但缺少真实的流动感。

本方案希望在不改变原始图片画风的前提下，让底部溪流自然流淌。

### 1.1 核心目标

- 溪流沿现有河道持续流动。
- 水面具有细腻的波纹、折射及动态反光。
- 保留原图中的石头、河床及水面纹理。
- 水流方向符合河道透视及转弯关系。
- 河岸、石头、草地等非水域内容保持静止。
- 支持白天与夜晚主题。
- 支持桌面与移动端。
- 动画异常时自动回退至静态背景。

### 1.2 非目标

首版不实现：

- 真实流体物理模拟。
- 3D 河床、水面网格及实时光线追踪。
- 交互式水花或鼠标扰动。
- 天气系统和降雨模拟。
- 水面与世界树之间的复杂物理互动。

首版重点是营造**持续、柔和、自然的视觉流动感**。

---

## 2. 最终技术选型

采用：

**静态背景 + Water Mask + Flow Map + Normal Map + WebGL Fragment Shader。**

使用 PixiJS 管理 WebGL 渲染、纹理和生命周期。

不使用 SVG 绘制水纹，也不采用简单的 CSS 背景平移动画。

### 2.1 技术组件

| 组件               | 功能                        |
| ------------------ | --------------------------- |
| PixiJS             | 管理 2D GPU 渲染            |
| WebGL Shader       | 实现水面纹理变形与动态反光  |
| Water Mask         | 限制水面动画区域            |
| Flow Map           | 定义水流方向与局部速度      |
| Normal Map         | 控制细小波纹的光照变化      |
| Background Texture | 保留原始图片的水面细节      |
| Static Fallback    | 不支持 WebGL 时显示静态场景 |

### 2.2 为什么使用 Shader

自然的溪流不仅需要纹理移动，还需要细微的局部变化。

Shader 可以对水面进行：

1. UV 位移：使现有水纹产生连续运动。
2. 局部折射：模拟水面下的河床轻微扭曲。
3. 法线扰动：产生细小波纹和动态反光。
4. 速度变化：让不同河段具有不同流速。
5. 边缘融合：避免水流动画出现明显裁切边界。

这些效果在片元着色器中完成，不需要 JavaScript 每帧修改大量 DOM 元素。

需要注意，单张静态背景无法恢复真实的三维水体。方案实现的是视觉上可信的水面动画，而不是物理准确的流体与反射计算。

## 3. 渲染架构

### 3.1 图层设计

```text
WorldTreeScene
│
├── StaticBackground
│   └── 原始场景图片
│
├── WaterEffectLayer
│   ├── WaterMask
│   ├── FlowMap
│   ├── NormalMap
│   └── WaterShader
│
├── ForegroundOcclusion
│   └── 石头、河岸等遮挡内容
│
└── StaticFallback
    └── WebGL 不可用时使用原图
```

### 3.2 渲染流程

```text
原始背景纹理
     │
     ├── Water Mask ────── 确定水域
     │
     ├── Flow Map ──────── 提供方向、速度
     │
     └── Normal Map ────── 提供波纹扰动
                 │
                 ▼
         Water Shader
                 │
                 ▼
      水面 UV 位移与动态高光
                 │
                 ▼
          Water Mask 混合
                 │
                 ▼
        静态背景 + 动态水面
```

建议在同一个坐标系中采样原始背景与水面效果，避免出现双层背景错位、变形或颜色不一致的问题。

## 4. 素材要求

### 4.1 文件结构

```text
public/assets/world-tree/water/
├── background.webp
├── water-mask.png
├── water-flow-map.png
├── water-normal.png
├── water-foreground.png
└── water-config.json
```

### 4.2 Background Texture

使用当前已经确认的世界树背景图。

要求：

- 保留原有画风。
- 保留河床、石头及水纹细节。
- 不重新生成整张背景。
- 不因动画造成明显的画质降低。

如果白天与夜晚使用不同背景，水域的几何位置应尽量一致。

### 4.3 Water Mask

采用灰度 PNG 或具有 Alpha 通道的纹理。

| 像素值 | 含义           |
| ------ | -------------- |
| 白色   | 完整水域效果   |
| 黑色   | 不应用水面效果 |
| 灰色   | 过渡与边缘融合 |

遮罩需要沿原始河道精确绘制。

特别注意：

- 河岸边缘。
- 水中的石头。
- 草地遮挡。
- 远景溪流。
- 河道转弯处。

对于边缘较复杂的区域，应当保留一定的柔和过渡，避免出现明显的水面贴图边界。

### 4.4 Flow Map

Flow Map 是整个方案的关键素材。

它不是普通水纹图片，而是记录水流方向与速度的纹理。

推荐采用以下约定：

| 通道 | 数据               |
| ---- | ------------------ |
| R    | 水流 X 方向        |
| G    | 水流 Y 方向        |
| B    | 可选的速度倍率     |
| A    | 可选的有效区域权重 |

其中 R、G 将 0～1 映射为 -1～1 的二维方向向量。

需要明确：方向和速度必须由同一套编码约定解释，避免绘制工具和 Shader 对通道含义理解不一致。

Flow Map 必须根据实际河道绘制，不能直接用随机噪声替代。

### 4.5 Normal Map

Normal Map 负责水面的细小起伏与反光变化。

建议使用：

- 低振幅细波纹。
- 多尺度纹理。
- 可平铺纹理。
- 较弱的高频扰动。

Normal Map 不需要包含复杂大型水浪。

Yggit 场景中的溪流应当平静、细腻，而不是海浪效果。

### 4.6 Foreground Occlusion

用于覆盖原本应该位于水面上方的内容，例如石头、岸边植物。

此素材不是所有场景都必须存在。如果 Water Mask 已能准确排除这些区域，可以不单独制作。

## 5. 水流核心算法

### 5.1 基础原理

Shader 每帧根据时间和 Flow Map，计算水面纹理的采样坐标。

基本形式：

```glsl
vec2 direction = texture(uFlowMap, uv).rg * 2.0 - 1.0;

float speed = texture(uFlowMap, uv).b;

vec2 flowOffset = direction * speed * uTime * uFlowStrength;
```

上述代码仅用于说明 Flow Map 的解码过程。

**生产环境不建议直接无限累加 `uTime` 到采样坐标**，否则可能发生纹理偏移过大、采样越界及循环跳变。

### 5.2 推荐：双相位流动

使用 Flow Map 的双相位采样方式。

两个循环相位错开半个周期，通过权重混合实现平滑、重复的水纹运动。

核心逻辑：

```glsl
float phaseA = fract(time * flowSpeed);
float phaseB = fract(time * flowSpeed + 0.5);

vec2 uvA = uv - flowDirection * phaseA * strength;
vec2 uvB = uv - flowDirection * phaseB * strength;

vec4 sampleA = texture(waterTexture, uvA);
vec4 sampleB = texture(waterTexture, uvB);

float blend = abs(phaseA * 2.0 - 1.0);

vec4 flowingWater = mix(sampleA, sampleB, blend);
```

实际实现需要结合纹理平铺、Flow Map 连续性与速度编码进行调整。

对于原始背景中的水面细节，建议只进行小幅 UV 扰动；主要流动感来自可循环的细节纹理和法线纹理。

不要对原始背景进行大幅平移，否则河床和固定反射也会跟着移动，产生不自然的效果。

### 5.3 运动方向

根据溪流透视，将河道分为：

**远景河段**

- 流速较慢。
- 波纹较细。
- 位移幅度较小。

**中景河段**

- 流速适中。
- 纹理方向跟随河道弯曲。
- 动态反光较明显。

**近景河段**

- 水面纹理变化更丰富。
- 可表现更明显的局部水纹。
- 不允许出现大范围画面扭曲。

具体速度由 Flow Map 控制，不需要把每一段水流实现为独立 Canvas。

## 6. 水纹与反光

### 6.1 双层法线扰动

推荐使用两组不同尺度的 Normal Map 采样：

- 第一层：较大尺度、缓慢流动。
- 第二层：细小尺度、不同速度。

将两层扰动适度叠加，产生自然的细节变化。

注意控制扰动幅度，避免出现类似水面沸腾的效果。

### 6.2 动态反光

反光效果应根据法线变化生成。

建议：

- 白天使用浅蓝白色高光。
- 夜晚使用低亮度青蓝色反光。
- 高光应呈不规则、细碎的分布。
- 不使用大面积周期性闪白。
- 保留原始背景中的静态光照关系。

因为当前使用的是 2D 图片，没有真正的环境反射数据，所以高光属于艺术化模拟。

不应过度增强，避免失去原图的绘画质感。

### 6.3 水域边缘处理

水面效果通过 Water Mask 混合：

```glsl
vec4 original = texture(uBackground, uv);
vec4 animated = computeWater(uv);

float mask = texture(uWaterMask, uv).r;

vec4 result = mix(original, animated, mask);
```

实际渲染时，还应处理背景纹理的采样边界，防止在河岸附近采样到不相关像素，造成颜色污染。

## 7. PixiJS 工程设计

### 7.1 组件结构

```text
src/
└── components/
    └── water-effect/
        ├── WaterEffect.ts
        ├── WaterRenderer.ts
        ├── WaterShader.ts
        ├── WaterController.ts
        ├── WaterAssets.ts
        ├── water.frag
        ├── water.vert
        └── water-config.ts
```

### 7.2 职责分工

**WaterEffect**

封装水流整体功能，供主页调用。

**WaterRenderer**

负责 PixiJS 初始化、Canvas 尺寸、纹理绑定和渲染资源管理。

**WaterShader**

实现 UV 位移、双相位流动、法线扰动和高光。

**WaterController**

负责启动、暂停、恢复和性能降级。

**WaterAssets**

负责加载和释放图片、遮罩、Flow Map、Normal Map 等资源。

### 7.3 渲染边界

建议只为水流效果创建一个局部渲染层。

不要将世界树、页面按钮、导航及全部文字都放进 PixiJS Canvas。

现有 HTML 页面仍按原来的方式渲染。

WebGL 仅负责水面动画。

## 8. 响应式方案

### 8.1 统一坐标系

所有素材使用统一的原始设计坐标。

包括：

- 背景图片。
- Water Mask。
- Flow Map。
- Normal Map。
- 前景遮挡层。

图片与水流 Canvas 应使用一致的缩放、定位和裁切逻辑。

例如页面使用 `background-size: cover` 时，需要将相同的缩放和偏移应用到水流渲染层。

### 8.2 PC 端

完整启用：

- 双相位流动。
- 双层法线扰动。
- 动态高光。
- 软遮罩混合。

### 8.3 手机端

保留核心 Flow Map 流动，但降低渲染成本。

建议：

- 降低水流层的内部渲染分辨率。
- 减少高频法线采样。
- 适当降低高光复杂度。
- 仅渲染手机实际可见的水域。
- 不改变水流方向和河道形状。

移动端不应该切换成完全不同的水流算法，以免 PC 与手机视觉效果差异过大。

## 9. 主题支持

白天、夜晚及未来季节主题共用：

- Water Mask。
- Flow Map。
- 运动计算逻辑。

主要调整：

- 水面颜色。
- 高光亮度。
- 法线扰动强度。
- 水面反射色调。

示例配置：

```json
{
  "day": {
    "flowStrength": 0.012,
    "normalStrength": 0.025,
    "highlightStrength": 0.45
  },
  "night": {
    "flowStrength": 0.012,
    "normalStrength": 0.02,
    "highlightStrength": 0.2
  }
}
```

上述参数仅为初始调试值。

如果白天与夜晚背景的河道几何不一致，则必须使用不同的遮罩及 Flow Map。

## 10. 性能与稳定性

### 10.1 性能控制

采用以下原则：

1. 仅渲染水域所需的画面范围。
2. 尽量减少 Shader 纹理采样次数。
3. 控制内部渲染分辨率。
4. 避免不必要的多次渲染通道。
5. 不使用 JS 逐像素处理水纹。
6. 纹理资源只加载一次。
7. 避免频繁创建和销毁 GPU 对象。

需要在实际手机上测试耗电、温度和滚动流畅度，不能只根据桌面浏览器帧率判断性能。

### 10.2 可见性管理

当水流区域离开屏幕：

- 暂停 PixiJS 渲染循环。
- 不释放仍可能很快复用的资源。

当页面进入后台：

- 暂停动画。
- 恢复后重新计算时间基准，避免水流突然跳动。

### 10.3 降级机制

| 情况                 | 处理               |
| -------------------- | ------------------ |
| WebGL 不支持         | 显示静态背景       |
| Shader 编译失败      | 关闭动画           |
| WebGL 上下文丢失     | 暂停并尝试恢复     |
| 恢复失败             | 静态回退           |
| 系统要求减少动态效果 | 禁用动画           |
| 检测到持续性能问题   | 降低渲染质量或关闭 |

静态背景必须独立于 WebGL 正常显示。

## 13. 最终技术决策

**采用 PixiJS + WebGL Flow Map Shader 实现世界树底部溪流动画。**

核心技术：

- Water Mask 限制水域。
- Flow Map 控制水流方向。
- 双相位 UV 采样实现连续流动。
- Normal Map 实现细腻波纹。
- Shader 生成少量动态高光。
- 静态背景保留原始画质。
- WebGL 不可用时自动降级。

最重要的实施原则：

**不要重新绘制一条河，而是在现有溪流上增加细腻、自然、可控的动态水面效果。**

第一阶段最值得投入精力的是 Water Mask 与 Flow Map 的准确制作。它们比单纯增加 Shader 特效更能决定最终水流是否真实自然。
