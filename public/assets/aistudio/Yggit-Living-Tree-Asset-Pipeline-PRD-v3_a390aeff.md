# Yggit Living Tree — 世界树素材拆分与动态主题基础规范 V3

> **文档类型**：需求文档 + 美术资产交付规范 + 技术对接说明  
> **阶段**：P0 默认世界树素材拆分；后续 P1 风动、P2 昼夜、P3 四季与天气、P4 节日扩展  
> **目标使用者**：AI 拆图 Agent、美术人员、前端 Agent、验收人员  
> **母版来源**：用户确认的「世界树主题六宫格」左上角 **01 永恒·默认**。如果能获得这棵树的独立高清原图，优先使用；六宫格里的裁切图仅作为构图与风格参考。**不得使用另一次生成的白天大型世界树替代母版。**

---

## 1. 背景与核心决策

Yggit 官网已经拥有稳定的首页布局及世界树品牌形象。未来希望让世界树拥有风吹叶动、光能流动、自然昼夜过渡、四季叶色与节日装饰，且不用为每个时间段和节日重做整个官网或重新生成一棵树。

### 1.1 必须坚持的原则

1. **同一棵树**：树干、主枝走向、根系、主要分叉、整体树冠范围、位置和尺度保持一致。
2. **同一张首页**：导航、标题、按钮、功能卡片、Git 界面与各区块布局不因主题改变。
3. **固定品牌交互色**：按钮、Logo 和主要功能图标保持 Yggit 青绿色；自然环境可随主题变化。
4. **素材与效果分离**：贴图决定形态和材质；渲染代码决定光照、Glow、微风、节点脉冲和粒子。
5. **非破坏式拆分**：尽量提取原图实际像素，通过蒙版分层；允许局部修复遮挡，但不能把整个树重新生成。
6. **先还原，再动起来**：P0 不开发复杂动画；先达到原图重组合格，再进入变形与风场。
7. **持续扩展**：树木母版唯一，后续新增主题主要提交材质、覆盖层、纹理、配置和调度规则。

### 1.2 目标效果

- 静止时：拼装出的默认树与母版视觉接近，没有明显重影、断裂、失真、光晕翻倍。
- 微风时：几簇叶片略有前后/左右的错时摆动，风从一侧传到另一侧；树干和根系不晃。
- 早晨/白天/黄昏/夜晚：复用同一套树木材质，通过环境参数控制亮度、冷暖、雾和能量线亮度。
- 春夏秋冬：复用树骨架及动画锚点，替换叶色/花朵/霜雪等外观层。
- 节日：在既有季节、天气上叠加装饰包，不改变产品结构。

## 3. 原图输入要求

### 3.1 输入优先级

1. **最佳**：原始独立高清世界树素材（无文字、无 UI 遮挡、未压缩、尽可能保留透明通道）。
2. **可用**：高清完整树图，带环境背景但没有 UI 遮挡；需要先分离背景。
3. **受限**：六宫格左上角「01 永恒·默认」裁切图。仅可做低分辨率拆分验证；遮挡细节和可见像素无法凭空复原。
4. **不建议**：整张官网截图。树被产品 UI 遮挡时必须补绘，补绘内容不应当宣称与原图完全一致。

### 3.2 源图审计（必须先输出）

AI 先检查并记录：

- 像素宽、高、色彩空间、alpha 是否存在、原图压缩或锐化状况。
- 树冠可见区域、主干区域、根系可见范围。
- 哪些区域被 UI、文字或背景遮挡。
- 哪些“发光线”已与树皮/叶片烘焙在一起，不能无损剥离。
- 哪些叶簇可根据可见自然枝条清晰分区，哪些只有模糊混合边界。
- 是否适合执行高质量 P0。若源图不足，应报告限制并请求原始素材，**不能偷偷换树**。

**高分辨率要求**：按网页目标展示尺寸选取 1×/2× 资源；优先保留源图原生像素，不得通过无依据放大把细节标为“原生高清”。如果做超分辨率，须单独交付 `upscaled/` 并注明 AI 补细节。

## 4. 推荐分层方案

> 为了后期进行 Mesh Deformation，必须采用 **固定骨架 + 不规则叶簇 + 发光遮罩 + 粒子** 的组合。避免把整张原图当做一张可变形矩形。

| 层       | 文件 / 目录                           | 内容                                         | 运行时是否运动   | 强制程度             |
| -------- | ------------------------------------- | -------------------------------------------- | ---------------- | -------------------- |
| 背景     | `background/scene_clean.webp`         | 去掉树后的森林/天空（如有）                  | 环境可变化       | 有背景才需要         |
| 固定骨架 | `base/base_trunk.webp`                | 树干、粗枝、根系及稳定纹理                   | **不动**         | 必须                 |
| 细枝     | `branches/branch_flex_XX.png`         | 有可感知弯曲需求的小分枝                     | 轻微形变         | 建议                 |
| 树冠     | `canopy/cluster_01.webp` …            | 独立不规则叶簇，目标 8–15 簇，按实际结构调整 | 独立风动         | 必须                 |
| 前景叶片 | `canopy/front_cluster_XX.png`         | 少量近景叶簇，提升景深                       | 更明显但仍克制   | 可选                 |
| 纹理发光 | `masks/glow_mask.webp`                | 能量纹理发光区域的灰度权重                   | 代码驱动         | 必须                 |
| Git 节点 | `masks/node_mask.webp` + `nodes.json` | 发光节点像素及逻辑中心点                     | 闪烁/脉冲        | 必须（若源图有节点） |
| 光效参考 | `reference/baked_lighting.webp`       | 原图现有光晕参考，不默认重复叠加             | 仅视觉参考       | 建议                 |
| 粒子     | `particles/`                          | 可复用叶片、花瓣、小光点                     | 自由运动         | P1/P3                |
| 季节     | `seasons/`                            | 春花、秋叶、冬雪等外观覆盖                   | 跟随相应叶簇运动 | P3                   |

### 4.1 固定骨架 `base_trunk.webp`

- 包括主体树干、主要分叉、粗枝、根系，不能跟随风场移动。
- 保留原有树皮质感与可见细节。
- **树干图层不应包含大面积叶片**，否则叶簇摇动后仍留有“静态叶子幽灵”。
- 如枝条被叶子遮挡，优先保留可见像素；仅在需要露出背景时最小范围补绘。
- 保留原图已有“烘焙进树皮”的光纹，另标记代码可增强的区域；不要为了拆发光而破坏树皮。

### 4.2 叶簇 `canopy/cluster_XX.png`

- 目标 8–15 个，**数量不是硬性指标**。应依据自然分枝、遮挡、锚点、纹理连续性决定，不能为凑数字强行切碎。
- 使用不规则 Alpha 蒙版，**不要做矩形切块**。
- 每个叶簇尽可能对应一处真实枝条连接点；叶簇可包含小枝与叶片。
- 临近叶簇需留有视觉重叠/羽化区域，避免形变时产生空洞；重叠像素须处理避免静态叠加后过亮。
- 要区分前后深度层级，前方叶簇覆盖后方叶簇时，后方边缘需要适量补全。
- 靠近连接点的位移权重为 0 或接近 0，叶尖较高，禁止整个叶簇像卡片平移。
- 如果叶簇真实分割困难，优先少而精的簇，不得生成大量伪造叶片填补缺口。

### 4.3 细枝 `branches/branch_flex_XX.png`

- 仅拆明显细长、和叶簇自然连接的枝段。
- 可通过约束形变实现轻微弯曲；主干和粗枝保持静态。
- 对每根细枝标记 `rootAnchor`、`tipAnchor` 和刚度值。
- 如分层会造成不可接受的断裂，可以将细枝和对应叶簇合并，统一受约束变形。

### 4.4 发光 `masks/glow_mask.webp`

- 单通道灰度：黑=不发光，白=允许强发光，中灰=中等强度。
- 包括树干上的能量线、根系流光、树冠少量高光，不包含普通所有亮叶。
- 建议额外导出 `glow_emission.webp`（可选）：RGB 发光颜色参考，支持代码按昼夜或季节着色。
- **不要直接在颜色贴图上叠加大面积白色模糊辉光**；但无法无损移除的原图烘焙高光可以保留并注明。
- Bloom、呼吸、强弱、昼夜变化由前端代码完成。

### 4.5 节点 `node_mask.webp`、`nodes.json`

- 仅识别真实存在的发光节点；每个节点输出唯一 ID、中心点、半径和默认颜色。
- 节点位置在**母版坐标系**中记录，不以截图显示缩放后的坐标表示。
- 避免既在底图保留强节点光晕、又在代码叠加同等级光晕造成重复曝光。
- 允许保留节点实体/纹理底色，但动态光晕和闪烁由前端绘制。

### 4.6 背景 `background/scene_clean.webp`

- 如果源图有背景，拆成背景与树两个独立层；如本身是透明树图，不必虚构背景。
- 移除树木后的背景区域需要有限补绘，记录哪些像素属于 AI 推断。
- 若仅用于首页，优先复用现有网站背景，不必强行从树素材抽取另一套森林景观。

## 5. 统一坐标、锚点与动画权重

### 5.1 统一画布

- 所有主要层原则上以母版尺寸 `W × H` 输出、透明区域补齐，保证**直接按原点叠加可以重组**。
- 如需节省存储，可另导出裁切版，但必须在元数据中记录 `sourceRect`、`canvasSize`、`offset`，与全画布版本保持等价。
- 坐标以母版左上角为 `(0,0)`，x 向右，y 向下。标准化坐标 `u=x/W, v=y/H` 可供响应式缩放使用。

### 5.2 每个叶簇必须记录

| 属性                | 含义                         |
| ------------------- | ---------------------------- |
| `id`                | 稳定的叶簇 ID                |
| `file`              | 对应透明 PNG 路径            |
| `bounds`            | 在母版的矩形包围盒           |
| `anchor`            | 与枝条相连的固定锚点         |
| `depth`             | 遮挡关系与绘制层级           |
| `windWeight`        | 风场响应权重（0–1）          |
| `stiffness`         | 弹性/刚度系数                |
| `phaseOffset`       | 响应时差/初始相位            |
| `maxDisplacementPx` | 在母版尺寸下允许的最大位移   |
| `deformMask`        | 哪些像素允许形变的权重图     |
| `overlapGroup`      | 相互覆盖、需要联合检查的分组 |

元数据样例（**仅为结构示例，数值不能当作真实图像测量值**）：

```json
{
  "schemaVersion": "1.0.0",
  "treeId": "yggit-world-tree-default",
  "source": {
    "filename": "default_world_tree_original.webp",
    "width": 2048,
    "height": 2048,
    "sourceSha256": "REPLACE_WITH_REAL_HASH"
  },
  "coordinateSystem": "top-left-pixels",
  "layers": [
    {
      "id": "base-trunk",
      "file": "base/base_trunk.webp",
      "type": "static",
      "depth": 20,
      "offset": [0, 0]
    },
    {
      "id": "canopy-01",
      "file": "canopy/cluster_01.webp",
      "type": "deformable",
      "depth": 30,
      "bounds": [120, 80, 420, 340],
      "anchor": [390, 345],
      "offset": [0, 0],
      "windWeight": 0.42,
      "stiffness": 0.76,
      "phaseOffset": 0.15,
      "maxDisplacementPx": 7,
      "deformMask": "masks/cluster_01_deform.webp",
      "overlapGroup": "left-canopy"
    }
  ],
  "nodesFile": "nodes.json",
  "glowMask": "masks/glow_mask.webp"
}
```

### 5.3 形变边界约束

- 锚点附近保持静止；从枝条连接点向外按权重逐渐增大位移。
- Mesh 应用在**独立叶簇或细枝**，而不是整张树图或整个官网页面。
- 位移上限由素材尺度和视觉实测确定；上述样例中的 7 px 不是统一标准。
- 不允许沿着任意方向拉长叶片导致肉眼可见变形。
- 回弹要自然，不能突然跳回原点。

## 6. 素材格式和质量规范

### 6.1 格式

- **制作母版**：优先 PNG 32-bit RGBA；保留原始 PSD/分层工程文件（如果使用相关工具）。
- **遮罩**：8-bit 灰度 PNG（必要时可提高位深）；请明确 gamma/色彩空间，避免阈值偏差。
- **交付给网页**：可压缩为 WebP/AVIF，前提是透明边缘与细枝细节经对比验证。
- **数据**：UTF-8 JSON，稳定 ID 与相对路径。
- **预览**：完整母版重组 `preview_rebuild.webp`、透明棋盘预览、关键区域局部放大图。

### 6.2 Alpha 与边缘

- 叶片边缘保留抗锯齿、半透明像素。
- 避免黑边、白边、绿色抠图残留，尤其在日间背景下容易暴露。
- 应注意预乘 Alpha（premultiplied alpha）混合流程一致，避免纹理边缘暗边。
- 接缝处允许恰当覆盖，但最终叠加后的亮度不应明显高于原图。

### 6.3 版本追踪

- 记录源图文件名、哈希、处理工具、处理日期、导出版本。
- 原始图不得覆盖。
- 如果进行了生成式补绘或超分，单独保留推断区域遮罩和操作记录。

## 7. P0 具体任务拆解（给 AI 拆图 Agent）

### Task 0：审计源图

输出 `audit.md`：可用分辨率、树冠与骨架边界、遮挡位置、烘焙光效说明、风险列表。若质量不足，停止夸大式交付。

### Task 1：提取世界树主体

从背景移除树，生成 `tree_full_rgba.webp`，尽可能保持树冠细叶、主干、根系和发光细线。

### Task 2：生成固定骨架

制作 `base_trunk.webp`，保留树皮与主枝、根系。清除浮动叶簇，但不得过度平滑或篡改结构。

### Task 3：分解自然叶簇

按照枝条连接关系建立叶簇清单，目标 8–15 片，不强制。逐簇导出透明 PNG 和局部/全局锚点，制作 `cluster_XX_deform.png` 权重蒙版。

### Task 4：抽取发光与节点

分别提供 `glow_mask.webp`、`node_mask.webp`、`nodes.json`。明确原图中哪些光已被烘焙，避免后续重复叠加。

### Task 5：重组验证

利用同一画布/偏移/图层深度重组出 `preview_rebuild.webp`；同时导出 `difference.webp`（重组图与原图差异可视化）、`rebuild_report.md`。

### Task 6：交付文件与异常说明

输出所有资产、元数据和遗留问题列表。不得把未完成的叶簇或缺失的透明素材标记为完成。

## 9. P0 验收标准

### 9.1 必须通过（Go/No-Go）

- [ ] 使用的是用户指定的左上角默认世界树母版，而非新生成的其他树。
- [ ] 原始树形、主枝、树干、根系的结构和位置保持一致。
- [ ] 所有主要图层具有 Alpha 通道，尺寸与坐标基准一致。
- [ ] 至少得到可独立运动的合理叶簇集合；每簇都有连接锚点和层级。
- [ ] 重组预览无明显空洞、重影、接缝、突兀锐化或光效翻倍。
- [ ] 细枝、叶缘和发光线在 100% 显示比例下没有明显抠图毛边。
- [ ] `tree_meta.json` 可被程序解析，引用资源全部存在。
- [ ] 记录生成式补全/未知区域，不能把推断内容描述为原图精准提取。

### 9.2 量化检查（辅助，不替代目测）

- 与源图对齐（宽高/偏移）必须完全一致。
- 对**可直接比较的未遮挡像素**计算差异热图，观察细枝、叶缘、根系等重点区域。
- 建议计算 MAE/SSIM 或感知差异，但**不预设固定合格分数**；有透明、发光与补绘区域时，分数可能误导。
- 针对合成重组图分别在深色、浅色、棋盘背景下检查边缘。

### 9.3 最小演示

P0 的最小演示不是“动画”，而是一个切换视图：原图 / 重组图 / 差异图 / 单独叶簇层。能确认每一层确实来自母版，并可单独显示。

## 10. P1 动画对接要求（预留，不在 P0 实施）

### 10.1 推荐技术

- PixiJS 作为树木 Sprite、局部 Mesh 和粒子的主要渲染层。
- 网格变形只作用于叶簇/细枝，树干和根系保持静态。
- 风场控制提供 `windDirection`、`windStrength`、`gustiness`、`time` 等参数。
- 叶簇依照 `windWeight`、`stiffness`、`phaseOffset`、`deformMask` 独立响应。
- 默认动效轻微；低性能设备与 `prefers-reduced-motion` 允许静态降级。

### 10.2 动画验收

- 无整体树图橡皮拉伸效果。
- 不出现枝条断开或叶簇和锚点明显脱离。
- 风向切换和风力归零过程平滑。
- 粒子不遮挡官网主要按钮与文案。
- 页面失焦时暂停不必要渲染。

## 11. P2～P4 昼夜、季节、天气及节日扩展预留

### 11.1 昼夜：**不为每个时间画完整树**

通过环境参数配置而非整树贴图切换：

- `ambientBrightness` 环境亮度
- `temperature` 色温/冷暖倾向
- `glowIntensity` 树干与根系发光强度
- `nodeIntensity` 节点亮度
- `fogAmount` 雾浓度
- `backgroundTint` 背景色调

在清晨、白昼、黄昏、夜晚关键帧之间插值。**注意**：如果原始素材具有很强的不可分离夜间光照，单纯调亮不能获得真实白天效果，可能需要单独制作“中性基础材质”或更细致的光/阴影分层；仍不需要四个时间段各画一整棵树。

### 11.2 季节：复用骨架和锚点

- 春：在固定叶簇上增加樱花/花瓣材质。
- 夏：浓绿树冠，局部阳光与萤火。
- 秋：红金叶片，落叶粒子。
- 冬：覆雪/结霜层和少叶枝条；树干根系保持不变。

季节覆盖层应跟随对应叶簇锚点、蒙版与形变，不应像大面积固定图片悬浮在摇动树冠之上。

### 11.3 节日：作为增量包

节日素材优先通过锚点挂载，例如灯笼、灯带、小型装饰，保留原树干枝条。配置包可声明适用日期/地区/默认季节、所需基础效果及资源路径。新增效果类型可能需要一次性开发新渲染组件；已支持的装饰和粒子类型可仅发布素材与配置。

### 11.4 主题优先级

用户手动选择 > 用户主动订阅的节庆活动 > 自动节日/地区规则 > 自动季节 > 永恒默认；昼夜和天气是独立维度，并允许用户关闭。品牌 CTA 始终保留青绿色。

## 12. 主要风险与应对

| 风险                     | 表现                | 应对                                             |
| ------------------------ | ------------------- | ------------------------------------------------ |
| 源图分辨率不足           | 叶缘糊、拆分失败    | 寻找独立高清原图；先 POC，不伪造高保真           |
| 原图存在 UI 遮挡         | AI 无法真实复原树枝 | 记录遮挡区域，仅局部补绘并标注                   |
| 叶簇交叠复杂             | 摆动时露空洞        | 遮罩羽化 + 隐藏层补全 + 缩小形变                 |
| 光效已烘焙               | Bloom 重影或发白    | 保留发光参考图，代码限制增益，必要时重制中性材质 |
| 叶片被拉伸               | 橡皮效果            | 以叶簇锚点、局部网格与刚度约束替代整图 warp      |
| 动画影响页面操作         | 卡顿、遮挡 CTA      | Canvas 只覆盖装饰区域、按需降级、性能监测        |
| 四季材质与节点坐标不匹配 | 季节切换跳动        | 母版统一坐标和锚点，材质绑定同一层 ID            |
| 主题扩展引入安全风险     | 第三方脚本运行      | 只允许声明式配置和可信资源格式                   |
